対象: log/_pilot5 (63 局、gemma-4-31B-it、greedy)、scenarios/、scripts/extract_hidden.py、scratchpad の hidden/out (aiwolf_0001 の npz)。
再計算は inspect_pilot5.py の再実行 (docs 内の pilot5_inspect.txt は view check 6 件で切れており、残り 39 件と batch-vs-stepped 行が欠落) と、

## 結論 (3 行)

1. 統制の骨格 (prompt_token_ids の一致 2688/2688、stepped の chat プロンプト = batch のトークン列 9/9 setup 全 call、席/書き手ビューのバイト一致 45/45 局) は確認できたが、**process 筋書きが multi-private に役職・選択肢・最終立場を漏らしている** (aiwolf_0001/0002 の公開筋に「Benjamin の占いで Shizue が人狼」、cs_0003 の席筋に「Study Commons を支持」)。multi-private-process は「情報を増やさない計画」になっていない。
2. **stepped の占いが 4/4 件 無効** (書き手が batch 書式どおり `Shizue (werewolf)` と書き、`match_name` が弾いて `-> none`)。batch vs stepped は「結末の決め手だけの差」ではなく、占い情報の有無も違う。加えて batch と stepped は同一 vLLM に**同時投入**されており、分岐の大きさは並列負荷下の値。
3. hidden states の恒等性 (同一区間で cos ≥ 0.9998) は npz で再現したが、札位置は online/multi では生成点の 9 トークン手前 (`<turn|>…<channel|>` の前) で機能が違い、batch との cos 0.6〜0.8 を「目標と履歴の置き場所の差」と読むのは不当。N=3 で言えるのは配管の正しさと会計の定義までで、条件の順位・同等性・先出し固有性は言えない。

## 依頼された観点への回答

**(1) batch と stepped の分岐。** 「分割自体は効かない」は本パイロットでは**構成からの主張** (chat プロンプトのトークン列同一 9/9、同一区間の表現 cos ≥ 0.9998) としてしか支えられない。実測の分岐は 4〜21 行で、5/9 setup は数値以前にサーバ手続き (正規化・行順・期間終了) で分岐し、残りも並列負荷下・top-1 logprob のみの記録で「反転」は観測できていない。報告は「同一入力の同一性は検証した。出力の一致は vLLM の非決定性と手続き差で N 行まで」とし、#3 の修正後に雑音床を出す。

**(2) hidden states。** 恒等性検査の手続き (記録トークン列の再生、prompt_tokens との一致 46/46 call、位置 = n_tokens−1) は設計どおり。問題は位置の定義: batch/stepped の `**:` は予測位置、online/multi の `**:` は user 末尾で予測位置は 9 トークン後の `<channel|>`。空の思考チャネル (4 トークン `<|channel>thought\n<channel|>`) は全 server 条件に共通なので online/multi/public/private 間の比較は揃うが、batch/stepped との比較はトークン役割の差が混入する。cos の条件差を §5 で解釈しないこと。

**(3) vLLM の非決定性。** 「batch を 2 回回して分散を測る」は雑音床として妥当だが、負荷依存なので**本実験と同じ投入条件** (逐次か並列か) で測ること。先に `VLLM_BATCH_INVARIANT=1` を試す方が安い (効けば greedy の再現性を「ほぼ」でなく一致で言える)。弱め方: 「greedy かつ batch-invariant モード; それでも手続き差で N 行以降は別の台本」。

**(4) N=3 で判断してよいこと / いけないこと。** よい: 配管の正しさ (ビューのバイト一致、トークン列、解析失敗 #2)、会計の定義の妥当性 (#5, #6)、漏洩の有無 (#1)、計算コスト (prompt トークン/局: batch 1.5〜2.5k、stepped・online・multi 100〜230k)、分岐が起きる機構。いけない: 語数・Skip/Over・違反の条件順位、public ≈ private の同等性、先出しの方式固有性、分岐の大きさの統計、結末分布。「online の語数が batch と multi の中間 (24.6)」は目標 (全文 vs 1 行) の効果と整合するが 推測; 論文が将来課題にした「online の役割文を batch の置き場で使う」条件をパイロットだけでも 1 setup 回すと切り分けられる。「public の Skip/Over が private より多い」(cs R1T2 の Skip 10 は全席が T1 で調査先を宣言し終えた直後) は情報量の効果としてあり得るが 推測。

**(5) 評価に必要な情報。** 揃っている: 全条件の台本 (同一 CSV)、席/書き手ビューの決定的復元、票・処刑・調査の行、違反と正規化、語数、ペルソナとカード (setup)、prompt/生成トークン id と top-1 logprob。足りない: (a) 通知イベント (選択肢公開・朝の告知) の行がない (前回 B2) ので局所応答性の turn-1 層別と「前発話への応答」の基準が引けない; (b) `mentions` が全行 [] (前回 C5 未対応) で呼びかけ先がない; (c) 立場の推移 (人物一貫性) の注釈がない — 票は期間末のみ; (d) 調査結果の本文が CSV 行にあるかは未確認 (席ビューには出る); (e) Skip/Over は #6 の基準で再集計が要る; (f) 情報忠実の「先出し」は #5 の再定義待ち。

**(6) 本実験前に直すこと (順)。** #1 (筋書きの禁則と凍結、multi-private-process の定義見直し) → #2 (stepped の ACTION 解析) → #3 (逐次実行、batch-invariant、top_logprobs、生接頭辞) → #5/#6 (検出器と会計の定義) → #7/#8/#9 (header と筋書きの記録) → (5) の (a)(b)。あわせて docs の pilot5_inspect.txt を完全版に差し替える。
