## 1. LLM エージェント同士の多人数会話の問題 (multi-private の観察)

multi-private = 参加者ごとに独立した LLM、自席の情報だけを持ち、1 発話ずつ生成する、いわゆる普通のマルチエージェント。

| 問題 | 指標 | gemma-31B: single-batch vs multi-private | Qwen3.8: single-batch vs multi-private |
|---|---|---|---|
| 発話が長い | 1 発話の語数 (上限 40 語) | 14.0 vs 33.9 | 10.1 vs 21.5 |
| 上限に張りつく | 35 語以上の発話の割合 | 0.00 vs 0.49 | 0.00 vs 0.00 |
| 冗長 (同じ中身を長く言う) | 1 つの新しい内容あたりの語数 (L / G) | 15.1 / 10.4 vs 40.0 / 25.5 | 12.0 / 8.5 vs 27.3 / 14.7 |
| | 設定ごとの比 (multi / single) の中央値、single が低い設定数 | L 2.76 (90/90)、G 2.61 (90/90) | L 2.36 (90/90)、G 1.85 (88/90) |
| 言うことがなくても話し続ける | Skip + Over / 局 | 11.3 vs 2.9 | 4.4 vs 0.3 |
| 呼びかけの無視 | 名指しの質問に、本人の次の発話が応えた割合 (L / G) | 0.63 / 0.57 vs 0.22 / 0.25 | 0.65 / 0.61 vs 0.34 / 0.37 |
| | 名指しされて応えなかった質問 / 局 (L / G) | 0.7 / 0.8 vs 3.7 / 3.6 | 0.6 / 0.7 vs 1.8 / 1.7 |
| 定型的な付け足し | 文末に質問を付け足した発話の割合 | 3.9% vs 8.5% | 2.4% vs 7.6% |
| | うち「what do you think / shall we / do you agree / …, @X?」型の定型句 | 0.5% vs 1.6% | 0.2% vs 0.9% |
| 水増し (注釈) | 明らかに短く言える発話の割合 (L / G) | 2 / 6% vs 9 / 13% | 3 / 6% vs 3 / 12% |

注意:
- 「定型的」は締めの決まり文句そのものは少数 (1〜2%) で、冗長さの主因は同じ発話内の言い直しと上限まで話す長さ。報告では「文末に質問を付け足す」「受けの前置き (That's a fair point, X. But…)」を例で見せ、数値は 1 内容あたりの語数で示すのが安全。
- 水増し (padded) は判定者間一致が低い (κ 0.2) ので補助扱い。
- 内容の総量 (新しい内容の数/局) は multi がむしろ 1.4 倍多い (gemma L 34 vs 47)。「中身が少ない」のではなく「同じ量の中身を 3 倍の語数で言う」が正しい言い方。

## 2. single に生成させると問題が起きない

上表の左列。加えて:
- 位置を揃えると発話あたりの新しい内容の数は同程度 (gemma、ラウンド 1〜3 のターン 1〜3 で差 ±0.15)。single は内容が尽きるターン 3〜4 で Over して譲る。
- single の副作用: 全員の秘密を知る書き手なので、占い師が初回の占いで人狼を当てる (gemma 1.00、Qwen 0.77、偶然 0.25)。multi-private は偶然の水準 (0.27 / 0.23)。

## 4. 段階別の実験 (梯子) と 3 つの仮説

| 仮説 (single が良い理由) | それを切り分ける比較 | 結果 |
|---|---|---|
| ① 全知であること (全員の秘密を知っている) | multi-public (全知の席) vs multi-private、multi-public-stepped vs multi-private-stepped | **密度には効かない** (gemma 40.4 vs 40.0 語/内容、Qwen 28.2 vs 27.3)。効くのは整合性 (占い師の命中 1.00 → 0.27) と反論 (12 → 19)。 |
| ② 筋書きを作ってから生成できる (未来が決まっている) | multi-private-process (筋書きを与えた 1 行生成) vs multi-private、multi-private-stepped-process vs multi-private-stepped | **密度にはほぼ効かない** (gemma 41.0 vs 40.0、Qwen stepped 17.6 vs 15.1)。内容の総量と反論が少し増える。 |
| ③ 生成単位 (全文を 1 回で書くか、次の 1 行を書くか) | single-batch-stepped vs single-online (同じ全知の書き手で目標だけ変える)、multi-private-stepped vs multi-private (席ごとのまま目標だけ変える) | **主因**。single 内で 14.6 → 31.1 語/内容 (gemma)、席ごとでも目標を全文にすると 27.3 → 15.1 (Qwen) と single の水準に戻る。 |

条件の説明 (8 条件):

| 条件 | 誰が書くか | 情報 | 生成単位 (目標) | 筋書き |
|---|---|---|---|---|
| single-batch | 1 つの LLM (書き手) | 全知 | 台本全文を 1 回で | なし |
| single-batch-stepped | 同上 | 全知 | 同じ全文の要求を 1 行ずつ続ける (結末はサーバが決める) | なし |
| single-online | 同上 | 全知 | 次の 1 行 | なし |
| multi-public | 席ごとの LLM | 全知 (全員の秘密を全席に) | 次の 1 行 | なし |
| multi-private | 席ごとの LLM | 自席のみ | 次の 1 行 | なし |
| multi-private-stepped | 席ごとの LLM | 自席のみ | 全文の要求のまま自席ビューを続け、自分の 1 行だけ採る | なし |
| multi-private-stepped-process | 同上 | 自席のみ | 同上 | あり (結末を含まない過程の筋書き) |
| multi-public-stepped | 席ごとの LLM | 全知 | 同上 | なし |
| (補助) single-batch-process / multi-private-process | | | | あり (gemma のみ) |

統制: 同一モデル・同一ルール文・同一台本文法・同一の情報公開スケジュール、temperature 0。gemma はバッチ不変モード、Qwen は 1 件ずつ配信 + 設定ごとに同じサーバインスタンス。single-batch の反復は gemma 9/9 (パイロット)、Qwen 90/90 設定で全文一致。

要点 (報告の結論候補):
1. 冗長さ・長さ・譲らなさ・無視は、**生成単位 (次の 1 行を書く目標)** で生じる。全知も筋書きも主因ではない。
2. 席ごとの生成でも、全文を書く目標で 1 行を出す (multi-private-stepped) と、**筋書きの共有なしに** single の密度と、自席情報だけによる整合性を両立できる (Qwen で確認、gemma は判定中)。
3. 応答性と反論は multi で高いが、これも生成単位から来ており、stepped では single 並みになる。応答性は必須ではなく、無視が減る方が利点は大きい。
4. 別系統 (Qwen) でも同じ形。差は gemma の方が大きい。

## 6. hidden states の分析と、マルチエージェントの改善への示唆

生成直前の内部表現 (その行の最初のトークンを予測する位置) から、これから書く発話の性質を線形プローブで読み出す。入力特徴 (ラウンド、ターン、話者、それまでの発話数と語数) だけの基準線と比べる。

gemma-31B (中核 5 条件、最良層の R²、括弧は基準線):

| 復号する属性 | single-batch | stepped | single-online | multi-public | multi-private |
|---|---|---|---|---|---|
| 次の発話の語数 | **0.69** (0.39) | 0.68 (0.40) | 0.48 (0.31) | 0.59 (0.22) | 0.37 (0.30) |
| この話者がこの期間にあと何回話すか | **0.89** (0.79) | 0.89 (0.79) | 0.87 (0.91) | 0.81 (0.85) | 0.89 (0.93) |

読み: 全文を書く条件では、書く前の表現に「この行の長さ」と「自分がいつ譲るか」が入っている度合いが高い (基準線からの上積み: 語数 +0.30 vs 1 行ずつ +0.16、multi +0.07)。single の密度の機構の候補。

Qwen3.8 (8 条件、暫定): 次の発話の語数は single-batch 0.53 (0.38)、single-batch-stepped 0.40 (0.33)、multi-private-stepped 0.35 (0.31)、1 行ずつの条件 (online / multi) は負の R² (過学習。正則化の調整が要る)。「あと何回話すか」は Qwen では基準線がほぼ 1.0 (Qwen は 1 行ずつの条件でほとんど譲らないため、位置だけで決まる) で、比較に使えない。**Qwen のプローブは正則化を交差検証で選び直してから使う**。

示唆 (蒸留): multi-private-stepped は「各席が議論の残り全体を想像して書く」ので重い (毎回、全文の要求 + 続き書き)。その表現 (書く前に長さと譲りが決まっている状態) を、普通の 1 行生成の席に軽量に移せれば、筋書きの共有なしに密度と整合性を両立できる。教師と生徒が同じ自席の情報しか持たないので、情報の不一致の問題もない。人狼大会のような筋書きを共有できない場面でも使える。

## 補足: 応答性と「無視」の違い、無視の内訳 (2026-10-29 21:30)

- 応答性 (Responsiveness-W): 全発話のうち、自分の前の発話以降の特定の発話に反応している割合 (誰に向けられたかは問わない)。
- 無視: 自分が @ で名指しされて質問されたとき、自分の次の発話がその質問に応えていない割合。

名指しの質問の後、本人の次の発話が何をしたか (gemma-31B、L。G もほぼ同じ):

| 次の発話 | single-batch | multi-private |
|---|---|---|
| その質問に答えた | 64% | 24% |
| 自分宛ての別の質問に答えた | 2% | 9% |
| 質問ではない別の発言に反応した | 25% | 63% |
| 何にも反応していない | 10% | 5% |
| (応答性、全発話) | 52 | 73 |

Qwen (L): multi-private 36 / 5 / 56 / 3%、multi-private-stepped 64 / 2 / 17 / 18% (single-batch 65 / 1 / 22 / 13%)。

- 自分宛ての質問が 1 件だけのときでも multi は 21〜23% しか答えない (single 59〜65%)。呼びかけの多さは主因ではない (2 件以上たまるのは multi の質問の 27%)。
- 2 件以上たまったときは 3 分の 1 で別の質問者に答える (まとめて返す / 1 人を選ぶ)。注釈の応答先は 1 件だけなので、両方に答えた発話は片方としか数えられず、その分 (全体の 9% 程度) 無視は過大に出る。
- multi の無視の正体は「直前の発言への受けを優先して、自分宛ての質問を流す」こと。応答性の高さと無視の多さは同じ癖の表と裏。

冗長さの数値の裏づけ (例に使った設定、1 内容あたりの語数 L / G): aiwolf_0001 25.5 / 9.2 vs 65.0 / 30.1、candidate_selection_0007 16.7 / 16.7 vs 28.0 / 26.4、shared_living_0016 17.7 / 9.3 vs 32.0 / 30.6 (single-batch vs multi-private)。
